# Incident Documentation and Post-incident Review (DER.2.1.A3) -- evidence template

## Purpose

All security incidents must be documented from detection through to closure, capturing timeline, impact, root cause, remediation actions, and lessons learned; post-incident reviews must be conducted for significant incidents with findings fed back into the security programme.

## Evidence required

- Structured incident record template or ticketing system configuration showing the required fields (timeline, impact, root cause, remediation, lessons learned)
- Sample closed incident records demonstrating that all required fields are populated, covering at least one significant incident
- Post-incident review schedule and evidence of a recent review for a significant incident, including the review record and attendees
- Lessons-learned actions tracked in the remediation register, with assigned owners and target closure dates
- Evidence that the review cycle is defined and followed, such as a process document or management report referencing completed reviews
