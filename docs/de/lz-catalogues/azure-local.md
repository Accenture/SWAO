# Azure Local (azure-local)

Diese Seite beschreibt den Landing-Zone-Katalog `azure-local`, wie er mit SWAO ausgeliefert wird: den Anbieter und sein Souveränitätsmodell, die Regionen mit Datenresidenz und Zertifizierungen, wie der Katalog aktualisiert wird und wie Sie ihn als Ziel verwenden.

## Anbieter und Souveränitätsmodell

Azure Local (früher Azure Stack HCI) betreibt Azure-Dienste auf Hardware am eigenen Standort des Kunden und wird über Azure Arc verwaltet. Der Katalog bildet die beiden Betriebsarten als Regionen ab, weil sie sich in den verfügbaren Diensten und den Souveränitätsmerkmalen unterscheiden: `connected`, bei der die Verwaltungsebene in der Cloud von Microsoft läuft, und `disconnected` für Standorte ohne diese Verbindung.

Souveränitätsmodell: Die Daten der Workloads bleiben am Kundenstandort, daher ist das Residenzland als `OPERATOR_SITE` erfasst, und die Regionen gehören zu keiner Geografie; nennen Sie die Region ausdrücklich, zum Beispiel `azure-local:connected`. Die Betriebsart connected erfasst Zugriffsrechte nach US CLOUD Act und FISA Section 702, die ihre Verbindung zur Cloud von Microsoft widerspiegeln; die Betriebsart disconnected erfasst keine. Für Azure Local selbst sind keine Zertifizierungen erfasst.

## Zertifizierungen

Der Katalog erfasst für keine Region eine Zertifizierung. Ein Rahmenwerk, das eine Zertifizierung verlangt (zum Beispiel BSI C5), meldet daher für jede Region dieses Anbieters eine Zertifizierungslücke.

## Diesen Katalog verwenden

Geben Sie eine Region dieses Katalogs als Ziel der [Landing-Zone-Katalog-Bewertung](/de/assessment/landing-zone) an, auf der Kommandozeile oder in der `.swao.yml` der App:

```bash
swao lz catalogue show azure-local
swao assess --type landing-zone-catalog --app <app-id> --lz-cat-targets "azure-local:connected"
```

```yaml
assessment:
  landing_zone:
    targets:
      - azure-local:connected
```

Um die Fakten für ein Engagement zu korrigieren oder zu ergänzen, kopieren Sie den Katalog mit `swao lz catalogue copy azure-local` in den Workspace und bearbeiten `wsp/inputs/catalogs/lz-catalogues/azure-local/index.json`; die Workspace-Kopie hat dann Vorrang. Siehe [Landing-Zone-Kataloge anpassen](/de/runbooks/adapting-lz-catalogues).

Katalogfakten geben einen Stand zu einem Zeitpunkt wieder und sind keine Rechtsberatung. Prüfen Sie Datum und Konfidenz oben sowie die Verträge des Anbieters, bevor Sie sich auf ein Ergebnis stützen.
