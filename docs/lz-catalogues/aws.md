# Amazon Web Services (aws)

This page describes the Landing Zone catalogue `aws` as shipped with SWAO: the provider and its sovereignty model, the regions with their residency and certifications, how the catalogue is refreshed and how to use it as a target.

## Provider and sovereignty model

Amazon Web Services (AWS) is the public cloud of Amazon Web Services, Inc., a US company. The catalogue covers the 34 commercial AWS regions worldwide and is generated from the endpoint data of the AWS SDK.

Sovereignty model: every region is operated by a US entity, so the US CLOUD Act and FISA Section 702 are recorded as extraterritorial exposure wherever the data resides. Frameworks that forbid this exposure (for example BSI C5) therefore block every AWS region, while frameworks without such requirements assess service availability only. In SWAO the catalogue is the hyperscaler reference point; compare it with `aws-esc` to see what the AWS European Sovereign Cloud offers.

## Using this catalogue

Name a region of this catalogue as a target of the [Landing Zone Catalog Assessment](/assessment/landing-zone), on the command line or in the app `.swao.yml`:

```bash
swao lz catalogue show aws
swao assess --type landing-zone-catalog --app <app-id> --lz-cat-targets "aws:eu-central-1"
```

```yaml
assessment:
  landing_zone:
    targets:
      - aws:eu-central-1
```

A geography such as `aws:Europe` instead of a region ID resolves to the default region shown in the summary.

To correct or extend the facts for one engagement, copy the catalogue into the workspace with `swao lz catalogue copy aws` and edit `wsp/inputs/catalogs/lz-catalogues/aws/index.json`; the workspace copy then takes precedence. See [Adapting LZ catalogues](/runbooks/adapting-lz-catalogues).

Catalogue facts are point-in-time and are not legal advice. Check the date and confidence above and review the provider's contracts before you rely on a verdict.
