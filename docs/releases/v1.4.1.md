# SWAO v1.4.1 release notes

Released 2026-10-20.

> v1.4.1 is the first public release of the 1.4 line. It contains everything described below plus one fix: the pass support catalogues (PII patterns, runtime end-of-life data, crypto algorithms, IAM providers) are now found inside the release binaries, so Pass 03, 05, 08 and 21 use them as intended.

v1.4.1 adds **Service Portfolio Assessment**, a fourth assessment type for the applications an organisation buys or operates rather than builds. Application, Landing Zone Catalog, and LLM Assessment produce the same outputs as before. The release also aligns every command with the documented licence tiers, gives every LLM provider the same retry and timeout behaviour, and hardens the MCP server; read [Breaking changes](#breaking-changes) before upgrading.

## Highlights

### Service Portfolio Assessment (`assessment.type: service`)

- **Excel intake to app folders**: `swao service init --from portfolio.xlsx` scaffolds one app per row, from the recommended template headers or a custom column map. Contact, phone, and e-mail columns are reduced to presence flags and never stored. German and mixed-language intake terms (criticality, TIME, classification, department names) are normalised to English, with the original wording kept next to them. [Getting started](/service-assessment/) and [Column mapping](/service-assessment/column-mapping).
- **Public research**: Pass 24 RESEARCH queries NVD, endoflife.date, CISA KEV, BSI CERT-Bund, OSV.dev, and (with your own key) VirusTotal, with caching, confidence, and provenance labels. [Optional API keys](/service-assessment/api-keys).
- **LLM-augmented research in every tier**: vendor profile, certifications, data residency, and breach history are researched with the configured LLM. Model-cited sources are marked unverified and the confidence of these topics is capped at medium. `swao service research --skip-llm` turns it off.
- **Installer analysis**: Pass 25 BINARY reads PE and MSI files without executing them: signature, certificate expiry, runtime, architecture.
- **INFRA-CAT classification**: 25 built-in categories with sovereign and open-source alternatives, cluster consolidation for identical servers, and engagement-specific Tier 2 extensions. [INFRA-CAT reference](/service-assessment/infra-cat).
- **Lift-and-shift cost estimate** in euro by default, other currencies configurable. Prices come from the Azure Retail Prices API and the AWS Price List API, with separate Linux and Windows prices, and are refreshed by `swao lz catalogue update`. [Configuration](/service-assessment/configuration).

### SWAO_APM community framework

The new framework `SWAO_APM` (72 controls in 11 domains, 47 scored automatically) produces a health score per domain, a weighted risk score, and a TIME recommendation (Tolerate, Invest, Migrate, Migrate-Critical, Eliminate) per application. A TIME label without end-of-life or CVE evidence is marked "insufficient evidence", and the portfolio headline figures cover assessed apps only. [Framework reference](/service-assessment/framework).

### Portfolio analytics

- **Combined portfolio view**: `wsp/portfolio-summary.json` lists application apps next to service apps, so TIME, waves, integration graph, and vendor consolidation cover both assessment types in a shared workspace.
- **5-wave migration generator** with blast-radius ordering and conflict warnings. [Migration waves](/service-assessment/migration-waves).
- **Integration graph and blast radius** from the intake integration column.
- **Vendor consolidation** grouping with opportunity scores.
- **Delta tracking**: each research run compares against the previous snapshot and writes a delta report; the last 4 snapshots are kept.
- `swao service rank` lists service apps in assessment priority order for top-N runs.

### Landing Zone Catalog

- **Targets in `.swao.yml`**: `assessment.landing_zone.targets` in the workspace or app `.swao.yml` (`<provider>:<region>` or `<provider>:<geography>`) drives the LZ Catalog run, the inline fit of an Application Assessment, and the TUI. The Setup Wizard has an LZ target step. [Landing Zone Catalog](/assessment/landing-zone).
- A run continues past a failing target (for example an unknown region), logs it, and closes as `partial`; skipped targets are shown in the report, the HTML publication, and the engagement hub.
- The LZ Sovereignty Challenge reads single-target runs correctly.
- `swao health-check` validates the bundled and workspace catalogues and the configured targets.

### Runs and reports

- Every application, service, and LZ catalogue run folder carries `run-status.json` (`started`, `complete`, `partial`, `failed`, or `aborted`), also after Ctrl+C or an unexpected exit; reports and summaries skip unusable runs.
- `swao report --run <id>` reports a specific application or landing-zone-catalog run.
- Reports and publications embed only the challenge of the reported run.
- `swao assess` without an LLM provider key warns and skips the LLM passes instead of waiting.

### LLM providers

- Anthropic, OpenAI, Ollama, the open-LLM gateway, and Bedrock share one request layer: 6 attempts with back-off on 408, 429, and 5xx, a per-attempt idle timeout (`SWAO_LLM_IDLE_TIMEOUT_MS`, default 120 s), a 600 s cap per attempt, and a `waiting` event every 60 s for long calls. SWAO Chat uses at most 3 attempts.
- `providers.llm.max_concurrency` (default 4) limits the LLM requests in flight per endpoint; compliance evaluation sends its batch prompts concurrently within that limit.
- Every provider writes the same event set to the SWAO logs. [Log events](/runbooks/log-events).
- SWAO Chat (Enterprise) supports tool calling with Ollama and Bedrock, and shows MCP errors to the model instead of empty results.

### MCP server (Enterprise)

- New tools for Service Portfolio Assessment results and runs: portfolio, app, research, waves, vendors, delta, scaffold, and runs, plus init, research, and export.
- All 55 tools validate their input and advertise a generated input schema.
- File tools read only inside the workspace root, `workspace_path` must be a SWAO workspace, and `app_id` is validated on every tool.

### Outputs

- Per-app service HTML publication with TIME, end-of-life, CVE, and blast-radius badges (Consultant+).
- Engagement hub cards for service apps and portfolio blocks: Migration Roadmap, Integration Hubs, Vendor Landscape.
- `swao service export` (Enterprise): a 14-sheet Excel workbook and 9 portfolio star-schema tables.

### Operations

- `swao health-check` grows from 16 to 25 probes, including a PII scrub audit and SWAO_APM weight and control validation. A missing credential vault is a warning.
- `swao support-bundle` includes service artefacts with a second PII redaction pass and `redaction-log.txt`, replaces the home directory, user name, and host name in every file, and records challenge statistics.
- `swao init` writes the workspace `.swao.yml` when it is missing; `swao init --reconfigure` without `--name` reconfigures the workspace only.
- The TUI offers **Service Portfolio Assessment** as the second assessment type: after three questions (intake workbook, column map, scope) it runs the scaffold, research, assessment, and the Enterprise export without further prompts.

### Documentation

- New Service Portfolio Assessment guide (8 pages), a reference page for every analysis pass, a page for every community framework, and expanded assessment-type pages, all in English and German.

## Breaking changes

No assessment output changes in an incompatible way. The following changes can affect scripts, log consumers, or Community users:

- **HTML publications are Consultant+ for every assessment type**: `swao publish` (`--app`, `--lz`, `--llm`, `--combined`, `--block-profile`) and `swao report --format html`. Running assessments of every type and the text, YAML, and JSON reports stay in Community.
- **Power BI `.pbit` templates are Consultant+**: the Community binary does not include them and `swao init` on Community does not write them. `swao export` still writes the star schema in every tier.
- **MCP registration is Enterprise**: `swao mcp install`, `swao init --mcp`, and the Setup Wizard step refuse on Community and Consultant binaries and never overwrite a binary of another tier.
- **Renamed log events**: `provider.bedrock.retry`, `provider.llm.anthropic.tool-call-attempt`, and the app-scope `provider.llm.gateway.ok`, `.http-error`, and `.empty-response` are replaced by `provider.llm.<provider>.attempt`, `waiting`, `timeout`, `http-error`, `retry`, `ok`, `error`, and `connectivity-failure`. Update log filters and dashboards; the mapping is in [Log events](/runbooks/log-events).
- **Catalogue lists**: the community framework list, the SWAO-INFRA-CAT built-in list, and the LZ catalogue list are read from each artefact's own metadata. `_registry.yaml` and `lz-catalogues/index.json` are no longer read; a workspace catalogue copy needs its `meta` block.
- `assessment.lz_cat_targets` is deprecated and still read; move targets to `assessment.landing_zone.targets`.

## Fixes

- Publications: JSON embedded in the HTML page now encodes `<`, so text such as an application name can no longer end the embedded script block early.
- Portfolio summary: a stale pointer to a deleted service run no longer stops the summary.
- `swao assess --portfolio` and `swao report --portfolio` run every app in the binary.
- `swao export --no-bom` and `--no-templates` take effect.
- Reports and publications no longer print em-dashes or double dashes and show a localised `n/a` for missing data.
- Service runs apply Kubernetes and service-mesh blind spots only when the workload shows container evidence.
- Console log lines strip line breaks and control characters.

## Known issues

- An unexpected internal error in a short-lived Enterprise command writes a crash log but can leave the process running; stop it with Ctrl+C.

## Upgrade notes

- Apps scaffolded with a pre-release build may lack `assessment.regimes_active` or the `cost` block; run `swao service init --from <intake.xlsx> --refresh` to add them.
- Optional: add `NVD_API_KEY` and `VT_API_KEY` to the credential store before the first `swao service research`.
- Re-run `swao mcp install` with the Enterprise binary after upgrading, with Claude Desktop closed.
- Move LZ catalogue targets from scripts or `--lz-cat-targets` into `assessment.landing_zone.targets` in the workspace `.swao.yml`.
